# G5 Loot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Seed every generated dungeon floor with scarce scatter loot, chests, gold piles, and occasional locked doors, drawn from a new dedicated `loot-placement` RNG stream, with area-scaled encounter density.

**Architecture:** A pure `placeFloorLoot` pass (new `packages/engine/src/loot-placement.ts`) runs at the tail of `placeFloorPopulations`, after the fragment spawn. Content gains a `currency` item category (`item.gold-coins`), three floor-scatter and three chest-tier loot tables, and a `floorLoot` balance block. The engine gains the `loot-placement` RNG stream (save v11→v12) that also takes over `fillItemSlots`/`placeFragmentSpawn` from the `encounters` stream, and a `currency.collected` event credited to `hero.currency` on pickup.

**Tech Stack:** TypeScript 5.8 ESM, Zod (strict), Vitest 3.2, npm workspaces (`@woven-deep/content`, `@woven-deep/engine`, `@woven-deep/web`).

**Spec:** `docs/superpowers/specs/2026-07-28-g5-loot-design.md` (read it before starting any task).

## Global Constraints

- **Determinism is the product.** No `Math.random`, no clocks, no Node APIs in `packages/engine` (enforced by `test/browser-boundary.test.ts`). Every consequential roll draws from a named RNG stream and threads `Uint32State` forward. Checked integer arithmetic only — no floats (percent knobs are integers 0–100 rolled via `rollDie(state, 100)`).
- **Demo hashes:** the 7 fixtures in `packages/engine/test/fixtures/*-demo-hashes.json` WILL drift starting at Task 1 (content hash changes). Do NOT re-pin mid-plan. Demo/CLI suites are expected red between Task 1 and Task 11; per-task test gates run the targeted suites listed in each task, not the root gate. Task 11 re-pins once with a per-fixture explanation in the commit body.
- **Build gotcha:** demo scripts and CLI tests import compiled `packages/engine/dist`. Before any engine test run that loads the default content pack, rebuild: `npm run build --workspace @woven-deep/content && npm run build --workspace @woven-deep/engine`.
- **GitNexus:** run `impact({target: "<symbol>", direction: "upstream"})` before modifying any existing function; run `detect_changes()` before each commit. Index may lag new files — that's fine, still run it.
- **Prettier:** run `npx prettier --write` on every touched file before each commit (two prior CI failures came from unformatted files).
- **Commits:** conventional, lowercase, no scope (`feat:`, `fix:`, `test:`, `docs:`, `chore:`). TDD is RED-first: run the failing test and confirm the failure message before implementing.
- **Save/content schema rules:** new engine state = save bump with a frozen legacy schema + exactly one ordered migration (Task 3 does this once; no other task may touch save schemas). Content schema bump v7→v8 happens once in Task 1.
- **Never leak hidden fields** through projections (RNG stream state, lock difficulty, chest table ids stay server/engine-side).
- Branch: `feat/g5-loot`. Do not push until Task 11.

```ts
export function depthBandFor(depth, bands): DepthBand {
  if (depth <= bands.shallowMaxDepth) return 'shallow';
  if (depth <= bands.midMaxDepth) return 'mid';
  return 'deep';
}

function rollRange(state: Uint32State, minimum: number, maximum: number): RandomStep {
  if (maximum <= minimum) return { value: minimum, state };
  const roll = rollDie(state, maximum - minimum + 1);
  return { value: minimum + roll.value - 1, state: roll.state };
}

export function placeFloorLoot(input, state): FloorLootResult {
  const { run, floor, content } = input;
  if (floor.depth < 1) return { items: [], features: [], state };
  const knobs = balanceEntry(content)?.floorLoot;
  if (!knobs) throw new RangeError('balance entry with floorLoot required for floor loot placement');
  const band = depthBandFor(floor.depth, knobs.depthBands);
  const protectedIdx = protectedRouteIndexes(floor);
  // candidate cells, row-major (deterministic): walkable, off protected routes, outside vault
  // rects, >= minimumAnchorDistance (Chebyshev) from stairUp/stairDown, no existing feature or
  // floor entity at the cell.
  // pick loop: while placements remain and candidates non-empty:
  //   const pick = rollDie(state, candidates.length); state = pick.state;
  //   take candidates[pick.value - 1]; drop every candidate within
  //   knobs.minimumSpreadDistance (Chebyshev) of it (including itself).
  // 1) scatter: rollRange(state, knobs.scatterCount.minimum, knobs.scatterCount.maximum) cells;
  //    per cell: createFloorLootFromTable({ content, tableId: `loot-table.floor-scatter-${band}`,
  //      state, itemIdPrefix: `item.floor-loot.${floor.floorId}.${n}`,
  //      floorId: floor.floorId, x, y, depth: floor.depth }); thread state.
  // 2) chests: rollRange over chestCount; candidate pool prefers wall-adjacent cells (>= 1
  //    orthogonal neighbor with !tileDefinition(tile).walkable), falling back to the full pool;
  //    lock roll: rollDie(state, 100).value <= knobs.lockedChestPercent → state 'locked' with
  //    lock { difficulty: knobs.chestLockDifficulty[band], keyContentId: null }, else 'closed',
  //    lock null. Feature: { featureId: `feature.floor-loot.${floor.floorId}.chest-${n}`,
  //      floorId: floor.floorId, x, y, contentId: null, coverTileId: floor.tiles[index]!,
  //      type: 'chest', lootTableId: `loot-table.chest-${band}`, lootContentId: null, state, lock }.
  // 3) doors: for each index with floor.tiles[index] === 2 (row-major), skip protected/occupied
  //    (existing run.features or newly placed features at that cell); rollDie(state, 100).value
  //    <= knobs.lockedDoorPercent → DoorFeature { featureId:
  //      `feature.floor-loot.${floor.floorId}.door-${n}`, ..., type: 'door', state: 'locked',
  //      lock: { difficulty: knobs.chestLockDifficulty[band], keyContentId: null } }.
  return { items, features, state };
}
```

Write it as real code (the comments above are the algorithm contract, including exact id and table-id formats). Every roll threads `state`; iteration orders are row-major index order so the pass is a pure function of `(run, floor, content, state)`.
